# Debugging a Project Mark task

| Finding | Repair |
|---|---|
| Models solve the core cleanly | Reconsider the empirical mechanism or source before adding packaging |
| Correct choice, materially wrong analysis | Grade substantive results fairly and inspect which findings matter |
| Low score from formatting or tight conventions | Repair the task/rubric interpretation; do not claim a valid analytical stump |
| Defensible methods give different winners | Resolve legitimate scope, constraints or missing evidence |
| Model result is better supported than golden | Fix the golden and dependent outputs |
| Essential variables are withheld | Narrow to a supported question or choose another appropriate source |
| Program refuses an unnecessary missing file | Correct the necessity check rather than inflating file counts |
| Response and rubric versions differ | Recover matching artifacts; do not merge scores |
| Source URL/license changed | Reverify current primary terms and preserve retrieval evidence |

Use [operative rules](../../shared-references/canonical-rules.md) for actual
thresholds. Avoid automatic task resets, skipped slots or unbounded reruns.
A reported historic context leak calls for checking solver inputs, not assuming
all high scores are contaminated.
