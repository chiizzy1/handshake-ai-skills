# Readiness checks

Use the current task UI and [operative rules](../../shared-references/canonical-rules.md).
The captured handbook's numbered checklist is historical and not proof of
present platform requirements.

Record actual evidence for each applicable check:

- task ID/start date/objective and correct specification;
- real, licensed inputs with necessary public fields and recoverable joins;
- inherited or current input counts, sizes and format requirements;
- a determinate decision and plausible consequential incorrect analyses;
- 1–3 appropriate outputs for a new task, or the applicable old contract;
- 25+ substantive generated criteria with legitimate tolerances;
- independently reproduced, consistent golden results;
- robust decision under reasonable analytical alternatives;
- blind screen status, separated from the official initial-response gate;
- exact prompt/ZIP/golden/rubric/response version match;
- final requested files opened/rendered and reviewed for business realism.

Do not significantly edit the rubric or import an old weight split as a new
requirement. Confirm current later-rollout and upload instructions in the UI.

A parser requiring a missing file is not proof the file carries necessary
evidence. A local linter PASS is not platform approval. A check not performed
is not run. Prepare reviewable artifacts within authorization; external
submission is a separate action.
