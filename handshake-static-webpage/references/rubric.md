## Core Purpose

In Static Webpage tasks, the worker is not evaluating two rendered websites. The worker is preparing a design brief that teaches an AI what kind of static webpage to build.

The worker gives the AI:

- a detailed written website description;
- 1 to 5 visual reference images;
- optional page assets meant to appear directly in the output;
- a target resolution.

The goal is to describe the desired webpage as if briefing a human designer.

## Four Submission Steps

### Step 1 - Write A Description

The description must:

- be at least 100 words;
- describe what someone would see scrolling from top to bottom;
- include specific colors;
- include layout structure;
- include sections;
- include mood and overall visual direction;
- match the assigned website category.

The description should not be a short generic sentence.

### Step 2 - Upload Reference Images

Upload 1 to 5 reference images.

Reference images are the most critical part of the task.

Valid reference images include:

- screenshots of real websites;
- design mockups;
- prototypes;
- visual examples that capture the intended website vibe;
- photos that communicate a color palette, mood, or styling direction when relevant.

Reference images are inspiration. They are not necessarily copied directly into the final output.

### Step 3 - Upload Page Assets

Page assets are optional.

Use Page Assets for files that should appear directly in the final webpage output, such as:

- logos;
- brand marks;
- high-quality background photos;
- product photos;
- specific images that the finished page must use.

Do not upload a required logo only as a reference image if the goal is for that exact logo to appear in the finished site.

### Step 4 - Select Target Resolution

Choose the target resolution that matches the design intent:

- Desktop;
- Tablet;
- Mobile.

Do not leave the target resolution blank.

Use the page structure to decide. A full horizontal nav, multi-column grid, and centered large hero image generally indicate Desktop.

## Strong Description Requirements

A strong description names specific visible design choices.

It should include:

- background colors;
- accent colors;
- typography style or feel;
- section order from top to bottom;
- hero section structure;
- navigation layout;
- card/grid/list structure;
- image placement;
- spacing or density;
- mood, such as editorial, premium, playful, calm, corporate, energetic, minimalist, boutique, or magazine-like;
- category-specific details, such as products for an online store or article cards for a blog.

### Strong Description Example Pattern

Good:

`The page opens with a dark navy hero section using warm cream text and a large lifestyle product photo on the right. A slim top navigation bar spans the width with the logo on the left, category links in the center, and a rounded cart button on the right. Below the hero, the page moves into a three-column product grid with soft beige cards, subtle shadows, and muted olive accent labels...`

This is strong because it describes colors, layout, sections, mood, and top-to-bottom structure.

### Weak Description Pattern

Weak:

`I want a clean, modern online store that looks professional and sells clothing. It should be easy to navigate and have good visual appeal.`

This is weak because it does not provide:

- specific colors;
- concrete layout;
- section order;
- visual mood beyond generic adjectives;
- enough detail for a designer or model to build from.

## Minimum Word Count

The written description must be at least 100 words.

Even if a description is specific, it is not ready if it is under 100 words.

If the description is 42 words, it must be expanded with more:

- colors;
- mood;
- section details;
- card layouts;
- typography;
- imagery;
- spacing;
- top-to-bottom structure.

Do not submit a description under 100 words.

The 100-word minimum is not category-specific. It applies broadly to the task.

## Reference Images

Reference images are critical because they show visual direction more precisely than text alone.

When choosing between polishing an already strong 300-word description and finding at least one reference image, prioritize finding and uploading the reference image.

### Reference Image Count

Allowed:

- minimum: 1;
- maximum: 5.

If the worker finds 7 good screenshots, choose the best 5.

Do not upload more than 5.

### Valid Reference Images

A valid reference can be:

- a live website screenshot;
- a partial page screenshot;
- a screenshot that shows a strong section style;
- a mockup;
- a prototype;
- a visual example that captures layout or aesthetic.

A reference image does not have to be:

- a full top-to-bottom page screenshot;
- a wireframe only;
- a design mockup only;
- from the exact same product category.

For example, an online store worker may use a real website screenshot if it clearly captures a useful visual style and layout.

## Page Assets Versus Reference Images

This distinction is important.

### Reference Images

Reference images are inspiration.

Use them to communicate:

- vibe;
- layout style;
- color palette;
- typography feel;
- mood;
- section composition.

The AI learns from them, but they are not necessarily inserted directly into the final page.

### Page Assets

Page assets are final-use files.

Use Page Assets for:

- a clinic logo that must appear in the website;
- a specific product photo to include;
- a background photo to place directly in the design;
- any high-quality image or logo that should be embedded in the finished output.

Do not upload the same logo to both sections just to increase the chance it is used. Put it in Page Assets if it should appear directly.

Do not put a logo link in the description field when the task provides a Page Assets upload section.

## Describing A Reference Layout

When a screenshot is used as a reference image, the written description should capture the main reusable design structure, not irrelevant exact text.

Prioritize:

- overall layout structure;
- major sections;
- color palette;
- mood;
- grid/card patterns;
- hero composition;
- nav placement;
- typography feel when it shapes the design.

Do not overfocus on:

- exact article headlines;
- exact navigation category names;
- source site credits;
- tiny page text;
- one small form or headline if the broader structure is the lesson.

### Blog Screenshot Example

If a blog screenshot has a colorful gradient hero at the top, a category navigation row below, and a three-column article card grid, the description should capture that structure and mood.

The category names and individual article titles are less important than the layout and visual system.

## Target Resolution

Choose resolution according to layout intent.

### Desktop

Choose Desktop when the intended design has:

- a full horizontal navigation bar;
- multi-column grids;
- large centered image compositions;
- wide editorial layouts;
- side-by-side content blocks;
- broad hero sections.

For a News page with a centered image, multi-column grid, and full horizontal nav, choose Desktop.

### Mobile

Choose Mobile when the intended design has:

- single-column stacked sections;
- mobile-style navigation;
- narrow viewport composition;
- thumb-friendly spacing;
- a phone-specific design intent.

Do not choose Mobile just because many people browse on phones. The target resolution should match the design being described.

### Tablet

Choose Tablet when:

- the design is specifically intended for tablet;
- the layout is neither phone-narrow nor full desktop;
- the reference and description imply a medium-width composition.

Do not choose Tablet merely as a safe middle ground.

## Assessment Answer Key Logic

Use this logic to answer the Static Webpage assessment.

### Q1 - Description Quality

The generic clothing store description is not ready.

Correct reason:

- it is too vague;
- it needs specific colors;
- it needs top-to-bottom layout structure;
- it needs overall mood.

### Q2 - Minimum Word Count

A 42-word description is not ready, even if specific.

Correct action:

- expand it to at least 100 words with more detail about colors, mood, and individual sections.

### Q3 - Most Critical Element

If a strong description is already written and time is short, prioritize uploading at least one reference image.

Correct reason:

- reference images are described as the most critical part of the task.

### Q4 - Reference Image Count

Maximum reference images:

- up to 5.

If there are 7 strong screenshots, choose the best 5.

### Q5 - Valid Reference Image

A screenshot of a real website that clearly captures visual style and layout is valid.

It does not need to show the full top-to-bottom page. It does not need to be a wireframe or mockup. It does not need to come from the exact same product category.

### Q6 - Page Assets Versus Reference Images

A high-resolution clinic logo that should appear directly in the finished webpage belongs in Page Assets.

### Q7 - Describing The Layout

For the blog screenshot, prioritize the overall layout structure:

- colorful gradient hero at the top;
- category nav below;
- three-column article card grid;
- colors and mood.

Do not prioritize exact article headlines or category names.

### Q8 - Target Resolution

A design with a centered image, multi-column grid, and full horizontal nav should use Desktop.

## Common Mistakes

- Treating reference images as optional when they are the most critical input.
- Submitting a description under 100 words.
- Writing generic adjectives without concrete design details.
- Describing only the hero and ignoring the rest of the page.
- Uploading a logo as a reference image when it should be a page asset.
- Uploading more than 5 reference images.
- Choosing Mobile because phones are common instead of because the intended design is mobile.
- Using Text-to-Code ELO scoring for a data-collection brief task.

## Final Checklist

Before finalizing:

- Is this Static Webpage data collection, not rendered-code ELO?
- Is the description at least 100 words?
- Does the description move top to bottom?
- Does it name colors, layout structure, sections, and mood?
- Are there 1 to 5 reference images?
- Are reference images treated as inspiration?
- Are final-use logos/photos treated as Page Assets?
- Is target resolution selected according to the layout?
- Does the answer match the assessment's exact question?
